## Data contract and rules

One row represents one NYC 311 service request. The input columns are unique_key, created_date, closed_date, agency, complaint_type, descriptor, status, borough and due_date. The data flow adds created_ts, closed_ts, due_ts and quality_reason.

The timestamps are interpreted in America/New_York and normalized to UTC. The first matching rule wins:

1. MISSING_ID — blank or absent unique_key.
2. INVALID_CREATED_DATE — creation timestamp could not be parsed.
3. INVALID_CLOSED_DATE — nonblank closing date could not be parsed.
4. NEGATIVE_RESOLUTION_TIME — closing timestamp precedes creation.
5. CLOSED_WITHOUT_DATE — status Closed but closing timestamp is absent.
6. VALID — no rule above matched.

The default output stream sends non-VALID records to Quarantine rather than dropping them. An absent due date or descriptor is allowed; an absent closing date is allowed for non-Closed statuses. Duplicate identifiers were checked in the audit, not rejected by the deployed data flow. A malformed due date is not a quarantine criterion in v0.1.

## Findings and limitations

All 13 quarantined records were DHS / Homeless Person Assistance requests with CLOSED_WITHOUT_DATE. This is a rule violation, not proof of an operational error; the agency may use different closure procedures.

Silver status counts: Closed 4962, In Progress 23, Pending 1, Open 1. Silver missing values: closed_date 25, descriptor 6, due_date 4943. Across the complete input, due_date was absent for 4956 of 5000 rows (99.12%), making general deadline analysis unreliable.

The selected source query filters January 2024 but limits the ordered extract to 5000 rows. Observed creation dates span 2024-01-01 00:00:00 through 16:40:40 New York local time. Source records can be updated after creation; the observed maximum close date was 2026-01-07. Treat this as a historical extract, not a point-in-time January 2024 snapshot or an unbiased sample.

Storage reduction compares combined output Parquet size against the Bronze CSV, including four added fields. It is not a controlled comparison of compression algorithms. The small sample does not establish scaling performance. ADF Copy Activity parses and reserializes CSV; Bronze preserves selected field values, not necessarily byte-identical source content.

## Reproduce locally

Install Python 3.11+ and the audit dependencies:

```sh
python -m pip install pandas pyarrow
python scripts/validate_outputs.py --bronze /path/to/bronze.csv --silver /path/to/silver --quarantine /path/to/quarantine
```

Each output argument can be a single Parquet file or a directory containing all Parquet parts for one run. The script checks this milestone's expected counts, schema, keys, original values, timestamp conversions and quality routing. Do not mix output files from multiple runs. Original files are intentionally not committed.
