# v0.2 — Closure Integrity Review

A small FDE-style product: help an operations analyst investigate incomplete closure records, calculate the affected share of an agency's selected batch, inspect supporting rows and export a review. NYC 311 is a public demonstration domain, not a customer engagement.

## What Azure does vs what we build

ADF and managed Spark acquire, normalize and classify the data; ADLS stores the outputs. The application uses the Azure Blob SDK and Microsoft Entra authentication to read two explicitly selected Parquet parts. It interprets existing quality classifications into agency-specific review cases; it does not recreate ingestion, transformation or a query engine. Only bounded batches (8 MiB per object, 10,000 rows total) are supported. Larger datasets must be summarized or queried in Azure.

The application is read-only and local-first for this milestone. No new Azure services or compute runs are required. No AI model is used yet. This is not a production or authenticated multi-user web service; do not expose it on a public interface.

## Run

From the repository root, using Python 3.11 or 3.12:

```sh
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-app.txt
python -m pytest -q
CORTEX_MODE=demo python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000. Demo mode is explicitly synthetic, not a reproduction of the historical metrics.

For the real Azure mode, authenticate with Azure CLI (`az login`, use the subscription/account that has Storage Blob Data Reader on the Silver and Quarantine containers). Find the exact two Parquet paths from the original transformation run in Storage Explorer. Then:

```sh
export CORTEX_MODE=azure
export CORTEX_AUTH=cli
export CORTEX_STORAGE_ACCOUNT=<your-storage-account>
export CORTEX_SILVER_PATH=<nyc311/exact-silver-part.snappy.parquet>
export CORTEX_QUARANTINE_PATH=<nyc311/exact-quarantine-part.snappy.parquet>
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Replace the placeholder values (do not enter the angle brackets). No access keys or SAS tokens are needed. For a future Azure-hosted app, use CORTEX_AUTH=managed_identity and grant its own identity Blob Data Reader. Both paths must belong to the same intended run; the current ADF outputs lack run manifests, so this is a manual selection. An Azure failure returns HTTP 503 rather than silently using demo data.

## Acceptance checks

With the original audited v0.1 output pair, expected counts are 5,000 total, 4,987 Silver, 13 Quarantine; one DHS review, 13 of 34 DHS records, 38.24%. These are baseline acceptance values from the original audit, not a claim that the new app has already been tested against live Azure.

Check that each evidence row is visible, the export contains the same evidence and blob ETags/SHA-256 hashes, and an unavailable Azure account causes a clear failure. The app does not infer a root cause or generalize from the historical sample. Agency-specific procedure remains a hypothesis, not a finding.

## Extension policy

Use subsequent course activities to extend the Azure data layer. Add managed analytical queries or Gold aggregates when needed, then consume them through the app. Introduce a managed AI service only when there is a specific business workflow and measurable evaluation. Do not rebuild Azure-managed infrastructure. Before a hosted deployment, add user authorization, privacy review, service identity, audit logging and threat modeling.
